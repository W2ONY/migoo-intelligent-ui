Migoo Intelligent UI 商品卡自适应配置台 · v0.1

参考 open-intelligent-ui 的架构：模型只写一份 UI 描述，布局由组件库渲染、不写死。Migoo 电商版把「模型」换成一个可配置的 策略引擎：读用户画像、查询与上下文，产出 卡片 Spec，再用 Migoo 现网组件（商品小卡 / 大卡 / feed 卡）渲染。左边调信号，中间看卡片，右边看它为什么这样画、改 Spec、查规范。

① 信号 Signals用户画像 · 查询意图 · 宿主上下文 · 商品状态
→
② 策略引擎 Policy规则库 × 优先级 × 注意力预算 × 现网约束
→
③ 卡片 Spec一份 JSON：槽位 · 强调等级 · 文案 · 顺序 · 排序权重
→
④ Migoo 组件渲染小卡 / 大卡 / feed 卡，只用现网 token

点任意一张卡 → 右侧显示它的决策追踪 / Spec / 约束检查。卡片样式全部来自 Migoo 组件库（商品小卡 · 大卡 · feed 卡）。

开关规则、改优先级，卡片立刻重算。蓝框 = 对当前选中卡命中。

怎么读这页：① 信号是引擎的全部输入，没有别的隐藏状态；② 每条规则 = when（JS 布尔表达式）→ effects（对 Spec 路径的 set / max / min / push / add）；冲突按 硬性约束 > 宿主上限 > 优先级（同级时 when 更具体者胜）> 注意力预算 裁决；③ Spec 是唯一的渲染输入，手动改 JSON 就能得到任何组合；④ 渲染只用 Migoo 组件库的 token（角标是现网的 12/65% 点分文本行，不是新 chip；价格 2 级用 18 Bold、3 级用 PDP 的 24 Bold），越过现网 CTA 矩阵的规则会在「约束检查」里标 需设计拍板。 架构对照：open-intelligent-ui 里「模型 → OpenUI Lang → 组件库」，这里是「策略引擎 → 卡片 Spec（JSON / Migoo UI Lang）→ Migoo 组件库」；换成模型驱动时，只需让模型输出同一份 Spec。
